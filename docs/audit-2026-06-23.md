## 3. globals.css 粉色变量分布

**45 个粉色相关变量**——这是真正的"重灾区"

按命名规则分类：
- **现代 P1 系**：`--color-pink-*` (~15 个：base/soft/strong/50/100/.../900)
- **legacy 首尔女生系**：`--pink-primary` / `--pink-soft` / `--pink-strong` (~6 个)
- **desktop 系**：`--desktop-pink` / `--desktop-pink-bg` (~4 个)
- **flashcard 4 套主题**：每套 5 个粉色变量 = 20 个

### 真值粉色清单
通过 grep 找到的实际十六进制：
- `#ff7fa8` — 出现频率最高（plan 假设的"主品牌色"）
- `#FF8FAB` — 跟 ff7fa8 不是同色（混用错位）
- `#FFB3C6`、`#FFD6E0`、`#fff0f5`、`#ffe4ee` — 浅粉变体
- `#ff8eb0`、`#f0799b`、`#e55a87` — 深粉变体
- `#f6c9c0` — Diary 胶带粉

**收口策略修正**：
- 一套统一 OKLCH scale 替代所有十六进制
- legacy 变量保留 alias 至少 2 周
- flashcard 4 套主题**保留**（独立闪卡场景，色板特殊化是合理的）

## 6. 最重要的 5 个修正决策

### 修正 1：数据文件不参与本轮升级
`grammar-cards*.ts` 和 `korea-articles/*.html` 的硬编码粉色（约 1040 处）属于内容数据，不在视觉系统范围。本轮只动 UI 层。

### 修正 2：grammar/page.tsx 独立 batch
505 处 inline 是个体超大的页面。原 plan 把它和别的页面打包，应该改成"grammar 单独占一个会话"。

### 修正 3：flashcard 4 套主题保留不动
独立场景，合理特殊化，不要强行收口。

### 修正 4：先做 PageHeader 全站推广
PageHeader.tsx 已经 token 化但只用了 14 处。把它推到所有页面顶部，工程量小但视觉一致性立刻飞跃。

### 修正 5：每个高风险文件独立 commit
原 plan 13 个 commit。grammar/kpop/[id]/typing/ai/analyze/news/[id] 各占 1 个，加上 5 个 TabBar 各占 1 个 = 至少 18 个 commit，不是 13。
